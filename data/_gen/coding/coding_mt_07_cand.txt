User: when should I use dynamic programming
Joe: Use dynamic programming when a problem has optimal substructure and overlapping subproblems. Optimal substructure means the best solution for the big problem comes from best solutions for smaller ones. Overlapping subproblems means the same smaller problems get solved many times.
User: what does overlapping subproblems look like in code
Joe: Fibonacci is the classic example: fib(5) calls fib(4) and fib(3), and fib(4) calls fib(3) again. That repeated work is the overlap DP eliminates.

User: what is optimal substructure exactly
Joe: A problem has optimal substructure when the optimal solution to the full problem contains optimal solutions to its subproblems. Shortest paths have it, because a shortest path from A to C through B includes a shortest path from A to B.
User: and what problem famously lacks optimal substructure
Joe: Longest simple path. The longest path from A to C through B does not necessarily contain the longest path from A to B, because the simple path constraint makes subproblems interact.

User: what is memoization
Joe: Memoization stores the result of a function call the first time it runs and returns the cached value on later calls. It turns naive recursive Fibonacci from exponential time into linear time by skipping repeated work.
User: so it is just caching function results
Joe: Exactly. A dictionary keyed by the arguments holds the computed value. Before recursing, check the cache; if found, return it without recomputing.

User: what is tabulation in DP
Joe: Tabulation fills a table iteratively from the smallest subproblems upward. Instead of recursion with caching, you compute dp[0], dp[1], dp[2] in order until you reach the answer.
User: so it is bottom-up instead of top-down
Joe: Right. Tabulation avoids recursion overhead and stack limits, and often uses less memory because you only keep needed rows. The tradeoff is you must figure out the fill order.

User: when should I pick memoization over tabulation
Joe: Memoization is easier when the recurrence is complex or not all states are needed. Tabulation is faster and safer for dense problems where every subproblem gets solved.
User: what do you mean by not all states being needed
Joe: In some problems, like the knapsack with many items but a tight capacity, memoization only computes reachable states. Tabulation fills the whole table even for unreachable capacity values.

User: how do I convert a recursive solution to tabulation
Joe: Identify the dimensions of the state, create a table of that shape, then fill it in dependency order. The base cases go in first, then each cell depends only on earlier cells.
User: what is the hardest part of that conversion
Joe: Getting the fill order right. If a cell depends on cells in the next row, you must iterate so those dependencies are already computed. A topological order of the subproblem graph is what you need.

User: what is a greedy algorithm
Joe: A greedy algorithm makes the locally optimal choice at each step, hoping it leads to a globally optimal solution. It never backtracks or reconsiders past decisions.
User: when is a greedy approach safe
Joe: Only when the problem has the greedy choice property and optimal substructure. Making the best local choice must still leave an optimal solution for the rest. Coin change with US coins works; with arbitrary coin values it does not.

User: what is the greedy choice property
Joe: It means a globally optimal solution can be built by making the best local choice at each step. Proving it usually involves an exchange argument showing any optimal solution can be transformed into the greedy one.
User: how does an exchange argument work
Joe: Take an optimal solution that differs from the greedy choice and swap in the greedy choice without making things worse. By repeated swaps you show the greedy solution is also optimal.

User: what problems are solved by greedy algorithms
Joe: Minimum spanning tree with Kruskal or Prim, shortest paths with Dijkstra, and Huffman coding for compression. All have the greedy choice property.
User: and what looks greedy but is not safe
Joe: The knapsack problem with fractional items is greedy-safe, but 0-1 knapsack is not. Taking the highest value-per-weight item first can miss the optimal combination when items are indivisible.

User: what is the difference between greedy and DP
Joe: Greedy makes one irreversible choice per step and never looks back. DP explores all options through subproblems and guarantees optimality even when greedy fails.
User: so DP is more powerful but slower
Joe: Generally yes. DP takes more time and memory because it considers many subproblems. Greedy is faster when it applies, but it only applies to problems with the right structure.

User: what is backtracking
Joe: Backtracking builds a solution incrementally and abandons a branch as soon as it cannot lead to a valid solution. It systematically explores possibilities and prunes dead ends.
User: how is backtracking different from brute force
Joe: Brute force enumerates every candidate. Backtracking prunes whole branches early using constraints, so it can solve problems like N-Queens that brute force cannot handle at scale.

User: what is pruning in backtracking
Joe: Pruning stops exploring a path when it cannot possibly lead to a valid solution. In N-Queens, if placing a queen on a certain column conflicts, you skip that entire column without placing the remaining queens.
User: so pruning is what makes backtracking practical
Joe: Exactly. Without pruning, backtracking is just brute force. Good pruning heuristics can reduce exponential search to something tractable for moderate inputs.

User: how do I write a backtracking solver
Joe: Define a recursive function that extends a partial solution. At each call, try all valid choices, recurse on the extended solution, and undo the choice if the recursion fails.
User: what does the undo step look like
Joe: After the recursive call returns, restore the state to what it was before the choice. For N-Queens, remove the queen from the board. This reset lets the next iteration try a different value.

User: what is the sliding window technique
Joe: Sliding window maintains a contiguous subarray that moves across a sequence, adjusting its start and end as needed. It turns O(n^2) nested loops into a single O(n) pass for many subarray problems.
User: what kinds of problems need sliding window
Joe: Finding the longest substring without repeating characters, the smallest subarray with a given sum, or the maximum average of any k-length subarray. Any problem asking about contiguous subarrays or substrings.

User: what is a fixed-size sliding window
Joe: The window has a constant length k. You advance one step at a time, adding the new element and removing the old one, updating the result from the previous window.
User: what about a variable-size window
Joe: The window expands and shrinks based on a condition. You grow the right edge until the condition breaks, then shrink the left edge until the condition holds again, tracking the best result along the way.

User: how do I know when to use sliding window
Joe: When the problem asks for a contiguous subarray or substring and involves a monotonic condition that you can maintain while moving the endpoints. If the condition is not monotonic, sliding window may not apply.
User: what does monotonic condition mean here
Joe: If expanding the window always makes the condition harder to satisfy and shrinking always makes it easier, the condition is monotonic. Sum and distinct characters are monotonic; product with negative numbers is not.

User: what is the two-pointer technique
Joe: Two-pointer uses two indexes traversing a sequence, often from opposite ends or at different speeds. It replaces nested loops with a single pass, reducing time complexity by a factor of n.
User: what is the classic two-pointer problem
Joe: Checking if an array is a palindrome. One pointer starts at the left, one at the right, and they move inward comparing characters until they meet.

User: what is the fast and slow pointer pattern
Joe: Two pointers start at the same position but move at different speeds. It detects cycles in linked lists: the fast pointer moves two steps for every one step of the slow pointer, and they meet if a cycle exists.
User: what else is fast-slow used for
Joe: Finding the middle of a linked list in one pass. When the fast pointer reaches the end, the slow pointer is at the midpoint. It also works for finding the start of a cycle.

User: what is the opposite-ends two-pointer pattern
Joe: One pointer starts at index 0, the other at index n-1, and they move toward each other. It works when the input is sorted and you need to find a pair that satisfies a condition.
User: give an example problem for opposite-ends
Joe: Given a sorted array, find two numbers that sum to a target. Start pointers at both ends, and if the sum is too small, move the left pointer right; if too large, move the right pointer left.

User: what is the prefix sum technique
Joe: Prefix sums store cumulative totals from the start of an array. Once computed, the sum of any subarray from i to j is prefix[j] - prefix[i-1], giving O(1) range sum queries.
User: what kind of problems use prefix sums
Joe: Finding subarrays with a given sum, range sum queries, and balancing problems. With a hashmap of prefix sums you can find subarrays that sum to k in O(n) time.

User: what is the frequency counting pattern
Joe: Count occurrences of each value in a collection using a dictionary or Counter. Once counts are known, many questions about duplicates, anagrams, or most frequent elements become simple lookups.
User: how does frequency counting solve anagrams
Joe: Two strings are anagrams if their character counts match. Build a Counter for each and compare; if they are equal, the strings are anagrams. This avoids sorting entirely.

User: what is the difference between DP and divide-and-conquer
Joe: Divide-and-conquer splits a problem into independent subproblems and combines their solutions, like merge sort. DP handles overlapping subproblems where the same subproblem appears in multiple branches, caching results instead of recomputing.
User: so DP caches and divide-and-conquer does not
Joe: Right. Merge sort subproblems do not overlap, so caching buys nothing. Fibonacci subproblems overlap heavily, so memoization turns exponential into linear.

User: what is the state in a DP problem
Joe: The state is a snapshot of the variables that determine the subproblem. For grid paths it is (row, col); for knapsack it is (items considered, remaining capacity). The state dimensions define the DP table.
User: how do I find the state for a new problem
Joe: Identify what changes as you make decisions. The parameters of the recursive function that are not constants form the state. If the same parameter combination recurs, it is a valid state dimension.

User: what is the recurrence relation in DP
Joe: The recurrence relation defines how a state depends on smaller states. For Fibonacci, dp[n] = dp[n-1] + dp[n-2]. It is the formula that connects the problem to its subproblems.
User: how do I derive the recurrence
Joe: Think about what one decision does to the state. At each step you make a choice that reduces the problem to a smaller one. The recurrence expresses the optimal value of the current state in terms of the smaller states.

User: what is the base case in DP
Joe: The base case is the smallest subproblem that can be solved directly without further decisions. For Fibonacci, dp[0] = 0 and dp[1] = 1. Base cases anchor the recurrence so it terminates.
User: what happens if I get the base case wrong
Joe: Every result built on it will be wrong. The base case is the foundation of the DP table, so verifying it with small inputs is essential before trusting larger results.

User: what is the DP for longest increasing subsequence
Joe: dp[i] stores the length of the longest increasing subsequence ending at position i. For each i, check all earlier j where nums[j] < nums[i] and set dp[i] = max(dp[i], dp[j] + 1). The answer is max over dp.
User: what is the time complexity of that
Joe: O(n^2) for the basic version, with a nested loop comparing each pair. A binary search optimization brings it down to O(n log n).

User: what is the DP for edit distance
Joe: dp[i][j] is the minimum edits to convert the first i chars of string A to the first j chars of string B. If chars match, dp[i][j] = dp[i-1][j-1]; otherwise take the min of insert, delete, or substitute plus one.
User: what operations count as one edit
Joe: Insert a character, delete a character, or substitute one character for another. Each costs 1, and the DP finds the cheapest sequence of operations.

User: what is the DP for coin change
Joe: dp[amount] is the minimum number of coins needed to make that amount. For each coin, dp[a] = min(dp[a], dp[a - coin] + 1). Initialize dp[0] = 0 and the rest to infinity.
User: does this work for any set of coin values
Joe: Yes, DP handles arbitrary coin values, unlike the greedy approach which only works for canonical coin systems like US coins. DP always finds the true minimum.

User: what is the subset sum problem
Joe: Given a set of numbers, can you pick a subset that sums to exactly a target? dp[i][s] is true if the first i numbers can sum to s. The answer is true if dp[n][target] is true.
User: what are the practical applications
Joe: Partition problems, knapsack variants, and resource allocation. If you can split a set into two equal-sum subsets, that is the partition problem, a direct subset-sum variant.

User: what is the difference between top-down and bottom-up DP
Joe: Top-down starts from the full problem and recurses down, caching results. Bottom-up starts from base cases and iterates up. Both solve the same recurrence but differ in execution order and memory use.
User: which one is easier to write
Joe: Top-down is usually easier because you write the natural recursive solution and add memoization. Bottom-up requires figuring out the iteration order, which can be tricky for complex dependencies.

User: what is the optimal binary search tree problem
Joe: Given keys with access frequencies, build a BST that minimizes expected search cost. dp[i][j] is the optimal cost for keys i through j, trying each key as the root and combining left and right subtrees.
User: that sounds expensive to compute
Joe: It is O(n^3) with the standard DP. Knuth's optimization reduces it to O(n^2) when the cost function satisfies the quadrangle inequality, which it does for this problem.

User: what is the matrix chain multiplication problem
Joe: Given matrices A1, A2, ..., An, find the parenthesization that minimizes the number of scalar multiplications. dp[i][j] is the minimum cost to multiply matrices i through j.
User: what makes this a DP problem
Joe: The optimal parenthesization splits at some k, and the left and right subchains must also be optimal. That optimal substructure and the overlapping subproblems from different split points make DP the right tool.

User: what is the longest palindromic subsequence
Joe: dp[i][j] is the length of the longest palindromic subsequence in the substring from i to j. If chars at i and j match, dp[i][j] = dp[i+1][j-1] + 2; otherwise dp[i][j] = max(dp[i+1][j], dp[i][j-1]).
User: how is that different from longest palindromic substring
Joe: Subsequence does not need contiguous characters, so "babad" has "bab" as a substring but "babab" as a longer subsequence. Substring requires contiguity, which needs a different DP approach.

User: what is the DP for longest common substring
Joe: dp[i][j] is the length of the longest common suffix ending at positions i in string A and j in string B. If chars match, dp[i][j] = dp[i-1][j-1] + 1; otherwise dp[i][j] = 0. The answer is the maximum value in the table.
User: and longest common subsequence differs how
Joe: LCS allows gaps. If chars match, dp[i][j] = dp[i-1][j-1] + 1; if not, dp[i][j] = max(dp[i-1][j], dp[i][j-1]). The subsequence can skip characters, so it fills differently when chars do not match.

User: what is the traveling salesman problem
Joe: TSP asks for the shortest route that visits every city exactly once and returns to the start. It is NP-hard, but DP with bitmask states solves it in O(n^2 * 2^n), feasible for up to about 20 cities.
User: how does the DP work for TSP
Joe: dp[mask][last] is the shortest distance to visit the cities in mask, ending at city last. For each mask, try extending to any unvisited city. The answer is min over dp[all][last] + distance[last][0].

User: what is the DP for counting paths in a grid
Joe: dp[i][j] is the number of ways to reach cell (i, j). From the top-left, dp[i][j] = dp[i-1][j] + dp[i][j-1] when moving only down and right. Base case dp[0][0] = 1.
User: what if there are obstacles
Joe: Set dp[i][j] = 0 for obstacle cells. The recurrence still holds for free cells, and obstacles are simply unreachable, contributing zero paths to later cells.

User: what is the DP for maximum subarray sum
Joe: Kadane's algorithm keeps dp[i] as the maximum subarray sum ending at position i. dp[i] = max(nums[i], nums[i] + dp[i-1]). The answer is the maximum over all dp[i]. It runs in O(n) and uses O(1) extra space.
User: why does Kadane work as DP
Joe: It exploits optimal substructure: the best subarray ending at i either starts fresh at i or extends the best subarray ending at i-1. The subproblems overlap because each position appears in exactly one subarray ending there.

User: what is a greedy algorithm that fails
Joe: The coin change problem with denominations 1, 3, 4 and target 6. Greedy picks 4 then 1 then 1 for three coins, but the optimal is 3 + 3, only two coins. Greedy fails because the local choice is not globally optimal.
User: so how do I know if greedy is safe
Joe: Prove the greedy choice property, usually with an exchange argument or by showing the problem has a matroid structure. When unsure, DP is safer even if slower.

User: what is the exchange argument for greedy
Joe: Take any optimal solution and transform it step by step to match the greedy solution without worsening the result. If every step preserves optimality, the greedy solution is optimal.
User: give a concrete exchange argument example
Joe: For the activity selection problem, any optimal solution can have the earliest-finishing activity swapped in without reducing the count. By induction, the greedy choice of earliest finish is optimal.

User: what is a matroid in greedy theory
Joe: A matroid is a structure where greedy always works for finding a maximum-weight independent set. It requires finite ground set, heredity, and the exchange property. Many greedy problems, like spanning trees, are matroid optimization.
User: is every greedy problem a matroid
Joe: No. The coin change problem and Huffman coding are greedy but not matroid problems. The matroid framework covers one important class, but greedy applies more broadly.

User: what is the Huffman coding algorithm
Joe: Huffman coding builds an optimal prefix-free code by repeatedly merging the two lowest-frequency symbols. It uses a priority queue and produces a binary tree where frequent symbols get short codes.
User: why is Huffman greedy
Joe: At each step it merges the two smallest frequencies, which is the locally optimal choice. The greedy choice property holds because merging the smallest pair cannot hurt the optimal compression ratio.

User: what is the activity selection problem
Joe: Given start and end times for activities, select the maximum number of non-overlapping activities. Sort by end time and greedily pick the next activity that starts after the last selected one ends.
User: why does sorting by end time work
Joe: Picking the activity that finishes earliest leaves the most room for remaining activities. This greedy choice is optimal, provable by an exchange argument.

User: what is Dijkstra's algorithm
Joe: Dijkstra finds the shortest path from a source to all other nodes in a weighted graph with non-negative edges. It greedily expands the closest unvisited node, updating neighbor distances as it goes.
User: why must the edges be non-negative
Joe: Negative edges break the greedy assumption. Once a node is visited, Dijkstra assumes its distance is final, but a negative edge later could provide a shorter path. Bellman-Ford handles negative edges.

User: what is Prim's algorithm
Joe: Prim builds a minimum spanning tree by starting from an arbitrary node and greedily adding the cheapest edge that connects a visited node to an unvisited one. It grows the tree one edge at a time.
User: how is Prim different from Kruskal
Joe: Prim grows a single tree from one starting point, always adding the minimum edge from the current tree. Kruskal considers all edges globally in sorted order, adding edges that do not form a cycle, which can build disconnected forests that later merge.

User: what is backtracking used for in practice
Joe: Solving constraint satisfaction problems like Sudoku, N-Queens, crossword puzzles, and graph coloring. It is also the engine behind many AI search algorithms for puzzles and planning.
User: how does backtracking solve Sudoku
Joe: Find an empty cell, try each valid digit, check row/column/box constraints, recurse on the next empty cell. If a digit leads to a dead end, backtrack and try the next digit. Pruning by constraint checking makes it fast.

User: what is the N-Queens problem
Joe: Place N queens on an NxN chessboard so no two queens attack each other. Queens attack along rows, columns, and diagonals. Backtracking places one queen per row and checks column and diagonal conflicts.
User: how do you check diagonals efficiently
Joe: Use two arrays for the main diagonal index (row - col) and anti-diagonal index (row + col). Both are constant for a given diagonal, so conflict checks become O(1) array lookups.

User: what is constraint propagation in backtracking
Joe: Constraint propagation reduces the domain of variables before branching, narrowing choices at each step. For Sudoku, when you place a digit, remove it from the possibilities of all cells in the same row, column, and box.
User: does constraint propagation always help
Joe: It reduces the branching factor, which usually speeds up search. In some problems the overhead of propagation exceeds the savings, but for tight constraints like Sudoku it is essential for acceptable performance.

User: what is forward checking in backtracking
Joe: Forward checking looks ahead one step: when a variable is assigned, it removes inconsistent values from unassigned variables that share a constraint. If any variable becomes empty, the current assignment is pruned immediately.
User: how is that different from simple backtracking
Joe: Simple backtracking only detects failure after assigning the conflicting variable. Forward checking detects failure sooner by tracking remaining legal values for each unassigned variable.

User: what is the minimum remaining values heuristic
Joe: MRV picks the variable with the fewest legal values next. It fails fast: if a variable has no legal values left, the search prunes immediately, reducing the branching factor at deeper levels.
User: is MRV always the best variable ordering
Joe: Usually yes for constraint satisfaction. It minimizes the branching factor and detects dead ends early. The degree heuristic is a tiebreaker, picking the variable involved in the most constraints.

User: what is the least constraining value heuristic
Joe: LCV orders values for a chosen variable, trying the value that restricts other variables the least. It maximizes the chance of finding a solution quickly, useful when any solution will do.
User: when would I use LCV over a fixed order
Joe: When the problem has many solutions and you want any one quickly. LCV leaves more flexibility for the remaining assignments, reducing backtracking compared to a naive value order.

User: what is the sliding window for longest substring without repeating chars
Joe: Maintain a window of unique characters using a set or dictionary. Expand the right end, and if a duplicate appears, shrink the left end until the duplicate is removed. Track the maximum window length.
User: how do you detect the duplicate efficiently
Joe: Store each character's latest index in a dictionary. When you see a character already in the window, jump the left pointer to max(left, last_index[char] + 1). This avoids shrinking one step at a time.

User: what is the sliding window for minimum window substring
Joe: Given strings S and T, find the smallest substring of S that contains all characters of T. Use two pointers and a frequency counter for T, expanding right until all chars are covered, then shrinking left while coverage holds.
User: how do you track coverage
Joe: Maintain a counter for required characters and a variable for how many distinct characters have been satisfied. When the count equals the number of distinct characters in T, the window covers T.

User: what is the sliding window for max sum subarray of size k
Joe: Sum the first k elements as the initial window. Slide the window by subtracting the element leaving and adding the element entering, updating the maximum sum each step. O(n) time and O(1) space.
User: does this work for any fixed window problem
Joe: Yes, any problem that asks about a contiguous subarray of fixed length k can use this approach. The per-step update is O(1), making the whole solution O(n).

User: what is the sliding window for longest substring with at most k distinct chars
Joe: Maintain a dictionary of character counts in the window. Expand the right end, adding chars. When the distinct count exceeds k, shrink the left end until it drops back to k. Track the longest valid window.
User: what if k is very large
Joe: If k is at least the number of distinct characters in the entire string, the answer is the full string. The sliding window still works, just without ever hitting the shrink condition.

User: what is the two-pointer technique for removing duplicates from sorted array
Joe: One pointer iterates through the array, another points to the position for the next unique element. When a new value is seen, place it at the slow pointer and advance both.
User: what is the slow pointer doing exactly
Joe: It marks the boundary between the deduplicated prefix and the unprocessed suffix. Every unique element gets written at the slow position, so the first slow elements are the unique ones in order.

User: what is the two-pointer technique for container with most water
Joe: Two pointers start at the left and right ends. Compute the area between them and update the maximum. Move the pointer with the shorter line inward because moving the taller one cannot increase the area.
User: why is moving the shorter one correct
Joe: The area is limited by the shorter line. Moving the taller line inward reduces width without any chance of increasing height, so area cannot improve. Moving the shorter line may find a taller line that compensates for the reduced width.

User: what is the two-pointer technique for three-sum
Joe: Sort the array, then for each element, use two pointers on the remaining subarray to find pairs that sum to the negative of the current element. Skip duplicates to avoid repeating the same triplet.
User: what is the time complexity
Joe: O(n^2) because the outer loop runs n times and the inner two-pointer scan runs O(n) each time. Sorting adds O(n log n), which is dominated by the O(n^2) term.

User: what is the fast-slow pointer for finding the start of a cycle
Joe: After detecting a meeting point with fast and slow pointers, reset one pointer to the head and move both at the same speed. The point where they meet again is the start of the cycle.
User: why does that work mathematically
Joe: The distance from head to cycle start equals the distance from the meeting point to cycle start going forward. Floyd proved this by analyzing the distances traveled by each pointer.

User: what is the two-pointer technique for partitioning
Joe: Similar to quicksort partitioning, one pointer scans and another marks the boundary of the partition. When a value that belongs on the left is found, swap it with the boundary pointer and advance.
User: what is a practical use beyond sorting
Joe: Separating even and odd numbers, or moving all zeros to the end while preserving relative order. The same partition logic applies with different comparison predicates.

User: what is the frequency counting pattern for finding duplicates
Joe: Build a Counter of all elements, then iterate to find entries with count greater than 1. For finding one duplicate in a range, the sum or XOR trick avoids extra space.
User: what is the XOR trick for a single duplicate
Joe: XOR all elements with all numbers 1 through n. Every number appears twice except the duplicate, which appears three times, so the result is the duplicate. XOR eliminates pairs.

User: what is the prefix sum for subarray sum equals k
Joe: Compute running sums. For each prefix sum, check if prefix_sum - k was seen before. The count of previous prefix sums matching that value gives the number of subarrays ending at the current position that sum to k.
User: why does that work
Joe: If the sum from index 0 to j is S and the sum from 0 to i-1 is S - k, then the subarray from i to j sums to k. A hashmap of prefix sum frequencies makes this an O(n) lookup per position.

User: what is the difference between longest increasing subsequence and longest common subsequence
Joe: LIS finds the longest strictly increasing sequence within one array. LCS finds the longest sequence common to two arrays. LIS can be solved in O(n log n) with patience sorting; LCS is O(mn) with DP.
User: when would I use LIS in practice
Joe: Finding the longest chain of nested intervals, or determining the minimum number of queues for a set of tasks with start and end times. It also appears in comparing DNA sequences.

User: what is the DP for maximum product subarray
Joe: Track both max_so_far and min_so_far at each position because a negative times a negative can become the new maximum. Update both using the current value, previous max, and previous min.
User: why track the minimum
Joe: A negative product can become the largest positive product when multiplied by another negative. For example, in [-2, 3, -4], the max product is 24 from the whole array, which the min tracking captures.

User: what is the DP for house robber
Joe: dp[i] is the maximum amount that can be robbed from the first i houses without robbing adjacent ones. dp[i] = max(dp[i-1], nums[i] + dp[i-2]). The answer is dp[n-1].
User: can this be optimized to O(1) space
Joe: Yes. Only the last two values matter, so store prev1 and prev2 and update them in each iteration. O(n) time with O(1) space.

User: what is the DP for unique paths with obstacles
Joe: Same as the basic grid path DP, but set dp[i][j] = 0 when there is an obstacle at (i, j). The first row and column must also handle obstacles by stopping the propagation.
User: how do obstacles affect the first row initialization
Joe: For the first row, dp[0][j] = 1 until an obstacle is hit, then all subsequent cells are 0 because you cannot go around obstacles. Same logic applies to the first column.

User: what is the DP for word break
Joe: dp[i] is true if the first i characters of the string can be segmented into dictionary words. For each i, check all j < i where dp[j] is true and the substring from j to i is in the dictionary.
User: what is the time complexity
Joe: O(n^2) for the DP plus O(1) dictionary lookups. With n up to a few hundred, this is fast enough. Optimizing with a trie for the dictionary reduces substring checks for large dictionaries.

User: what is the DP for combination sum
Joe: dp[target] is the number of ways to reach that target using the given numbers. dp[t] = sum(dp[t - num] for num in nums if t >= num). Initialize dp[0] = 1 for the empty combination.
User: does order of numbers matter
Joe: In this formulation, yes, because (1, 2) and (2, 1) are counted as different combinations. To make order not matter, iterate numbers in the outer loop and targets in the inner loop.

User: what is the DP for partition equal subset sum
Joe: Check if the total sum is even, then find if any subset sums to total / 2. dp[s] is true if some subset of the processed elements sums to s. Update for each number from target down to the number.
User: why iterate target downward
Joe: Iterating downward prevents using the same element multiple times. If you iterate upward, the same number could be used repeatedly because the updated dp values would be used later in the same iteration.

User: what is the DP for decoding ways
Joe: dp[i] is the number of ways to decode the first i characters. dp[i] = dp[i-1] if s[i-1] is valid, plus dp[i-2] if the two-digit substring s[i-2:i] is between 10 and 26.
User: what makes a one-digit decode valid
Joe: Any digit from 1 to 9. Zero alone is not valid, but zero as part of 10 or 20 is fine. This creates edge cases around zeros that the DP must handle carefully.

User: what is the DP for interleaving strings
Joe: dp[i][j] is true if the first i+j characters of the target can be formed by interleaving the first i chars of s1 and the first j chars of s2. The recurrence checks matching the next char from either s1 or s2.
User: what is the space optimization for this DP
