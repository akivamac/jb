## 1. Project Genesis – Rules‑Based Monkey Joe (May 2026)

- **Initial Idea (May 1)**  
  Started as a simple rules‑based chatbot called *Monkey Joe*.  
  It answered questions with hard‑coded rules and a tiny set of templates.

- **Goal**  
  Eventually build a *learned* AI that could converse naturally and adapt to new information.

## 2. First Branch & CLI Integration – "Joe‑brain" (June 22)

- **Branch Creation**  
  `git checkout -b joe-brain` on 2026‑06‑22 18:40:46 ‑0400.

- **Claude CLI**  
  Used Claude's command‑line tools to scaffold files (`train.py`, `model.py`, `tokenizer.py`, etc.) and to start the first neural‑network training run.

- **Model Specs (Initial Letter-by-Letter)**  
  * Very small: ~500k parameters or less.  
  * 2-4 layers.  
  * Letter‑by‑letter tokenization.
  * Lowest loss achieved: ~0.1 (but model was later discarded).

## 3. Letter-by-Letter Training Issues

- **Major Bug**  
  One long training session encountered a critical bug that corrupted the model weights.  
  Exact cause unknown, but it made the model unusable.

- **Decision**  
  Switched to a token‑by‑token approach instead of trying to fix the letter‑by‑letter model.

## 4. Transition to Token‑by‑Token Generation (≈ July 1)

- **Why?**  
  Letter‑by‑letter generation was too slow and produced incoherent text.  
  Switching to token‑by‑token (word‑based) greatly improved fluency.

- **Implementation**  
  Updated the tokenizer to emit word tokens instead of single characters.  
  Adjusted the data pipeline accordingly.

- **Effect**  
  Loss dropped; the model started to capture word‑level semantics.

- **Total Training Steps on Token-by-Token Model (Before July 30)**  
  ~40,000 steps accumulated across multiple runs.

- **Lowest Loss Achieved on Token-by-Token Model**  
  ~1.2

## 6. Data Cleaning & Formatting (July 26-29)

- **Problem Discovered**  
  * Model was hallucinating ("I am'will toore").  
  * Training data was poorly formatted (raw facts without User:/Joe: prefixes).  
  * Data contamination: Multiple AI models added inconsistent answers to same questions.

- **Solution Applied**  
  1. Created `fix_data.py` to extract 880 conversation pairs from `make_conversations.py`.  
  2. Formatted them as:
     ```
     User: [question]
     Joe: [answer]
     ```
  3. Deduplicated exact duplicate lines.  
  4. Appended formatted conversations to `data/train.txt`.

- **Result**  
  `train.txt` grew to ~5.5M characters with proper turn-taking structure.

9. Model Growth (July 30)
Why Grow?
Need more capacity to learn long‑term dependencies and reasoning.

grow_model.py
A custom script that:

Expands embed_dim (192 → 256).
Adds layers (5 → 7).
Preserves existing weights in the "top‑left" block.
Zero‑initializes new weights (model behaves the same at first).
Zeros Adam moments for new weights (optimizer starts fresh).
Command

bash

Copy
python3 grow_model.py --new_embed_dim 256 --new_layers 7
Result

Parameters increased from 2.7M to 6.17M.
File data/model.npz now holds the enlarged model.
All prior knowledge preserved.

12. Key Insights
Data Format Matters: Consistent User:/Joe: prefixes teach turn-taking structure.
Model Size Matters: 2.7M was too small; 6.17M is better but still tiny.
Chain of Thought Helps: Examples with "Let's think step by step" improve reasoning.
Gradual Growth Works: Growing model preserves knowledge while adding capacity.
Temperature Affects Output: Lower temp (0.6-0.7) reduces hallucinations vs 0.9.
Token-by-Token Better: Switching from letter-by-letter dramatically improved quality.
